用户发起了完整投研流程，主题为：**$ARGUMENTS**

按以下编排执行（严格串行，上一阶段验收通过才进入下一阶段）：

## 编排流程

### 前置：公司选择（新增，在 Phase 1 之前执行）

产业调研涉及的公司范围较广，先让用户确认重点公司，避免遗漏或调研偏差：

1. 调用 `bun run sector.ts --search "主题"` 查找相关板块（取最相关 1-3 个）
2. 对每个相关板块调用 `bun run sector.ts --code <板块代码> --top 30` 获取成分股（按成交额降序）
3. 向用户展示成分股列表（前 15-20 只），请用户**多选**要重点调研的公司
4. 用户确认后，将选中的公司列表写入 `Research/00-Workspace/01-Inbox/YYYY-MM-DD-主题-company-selection.md`
5. 提供「跳过，由 Agent 自行选择」选项（若用户跳过，则 InfoHunter 按原有逻辑自行决定）

> InfoHunter Phase 1 采集时**优先覆盖用户选中的公司**，再补充其他代表性公司。

### Phase 1-6 标准流程

1. **Phase 1 信息获取** — 派发子任务 `info-hunter`：多源搜索（**三层结构**：行业级 / 细分行业级 / 公司级，按**充分性标准**采集——关键论点 ≥1 权威来源、核心数据 ≥2 独立来源交叉验证），使用信源导航与 bun 抓取脚本，下载财报 PDF 并用公共文件摄取 CLI 提取 Markdown 到 `pdf-texts/` 目录（**下载财报时须传 `--name "<可读标题>"` 落盘，禁止用源文件名**，命名规范见 AGENTS.md 共享脚本用法表），输出 `Research/00-Workspace/01-Inbox/YYYY-MM-DD-主题-raw.md`
   - 验收：文件存在、三层均有实质采集内容（非空壳）、每个关键论点有 URL 来源锚点、核心数据（营收/净利/估值）有 ≥2 独立来源交叉验证（其中业绩类数据回法定披露平台核对）、每家公司声明的财报 `.md` 在 `pdf-texts/<公司名>/` 中真实存在且 frontmatter 文件事实完整。单源支撑的关键论点须显式标注「单源支撑，置信度上限 6」。**不以来源总数作为通过标准**，不通过则打回补充。
2. **Phase 1.5 原文精读** — 派发子任务 `document-reader`：带着投资目的精读 Phase 1 采集的财报/研报/公告原文，搞清增长飞轮、业务模型、财务状况、竞争格局、管理层质量、风险与逆向检查、历史类比，**并强制精读最近 3 个完整财年年报**（判断基本面趋势/三年连贯性/管理层诚实，红线结论 9.3 必填），**同步完成多空论证（Bull Case / Bear Case）**（基于同一套原文证据挖掘多方增长飞轮/护城河拓宽/财务质量/估值安全边际与空方增长见顶/护城河侵蚀/财务红旗/估值过高/产能过剩地缘风险，双方均原文引用、区分事实与观点、强度/置信度分级、预判对方论点并回应、诚实记录脆弱点），输出 `Research/00-Workspace/02-Processing/YYYY-MM-DD-主题-deep-read.md`（**含第十章多空论证**）
   - 验收：9大精读目标均已覆盖（含三年年报趋势/连贯性/管理层诚实红线、扣非归因/指标波动归因/数据逻辑一致性检查，归因附外部证据或标注证据不足）、每条判断有原文出处（章节/页码）、发现的关键矛盾/红旗已显式标注、**第十章多空论证完整（多方/空方 Top 论点、五维度对照、对对方预判回应、脆弱点）**。不通过则打回。
3. **Phase 2 信息处理** — 派发子任务 `info-alchemist`：基于 document-reader 的认知笔记，执行清洗、结构化、口径标准化（按三层归类），输出 `Research/00-Workspace/02-Processing/YYYY-MM-DD-主题-processed.md`
   - 验收：关键事实清单完整、单位与时点齐全、三层数据均已归类、document-reader 的红旗/矛盾项已提取供验证。不通过则打回。
4. **Phase 3 交叉验证** — 派发子任务 `cross-validator`：多源比对、置信度评分、反共识检验（按三层逐条评分），重点验证 document-reader 的关键判断和原文引用，输出 `Research/00-Workspace/03-Validation/YYYY-MM-DD-主题-validated.md`
   - 验收：每条关键事实有评分、矛盾点有倾向判断、document-reader 的存疑项已独立验证。不通过则打回。
5. **Phase 4 信息整理** — 派发子任务 `knowledge-architect`：高置信度信息（≥8 分）**按三段式目录**（00-行业概览/01-细分行业/02-公司研究）写入 `Research/10-Knowledge/` 对应行业目录，公司信息不足时主动补充调研，更新 MOC，校验双向链接
   - 验收：三段式目录均有产出、知识节点 properties 完整、公司节点含优劣势、MOC 已更新。
6. **Phase 5 报告生成** — 派发子任务 `report-writer`：生成 Markdown 报告 + **独立 HTML 报告**（直接基于调研结果编写，图表 ECharts CDN 外链），写入 `Research/20-Reports/YYYY-MM-DD-主题-report.md`；**必须完成增长驱动与核心优势可持续性分析**（当前是否高增长、增长促成原因、未来增长因素内因/外因与企业主导性、相对同行的核心优势能否维持）并**综合 deep-read 第十章多空论证做裁决**
   - 验收：核心结论可回溯数据、md + html 双份产出、HTML 图表全部 ECharts 且独立编写（有数据支撑的图表才做，每图带数据锚点）、**增长驱动与核心优势可持续性分析章节已覆盖**。
7. **Phase 6 归档** — 将 `00-Workspace/01-Inbox|02-Processing/deep-read|02-Processing/processed|03-Validation/` 中的本次中间产物移入 `04-Archive/`，在归档文件 frontmatter 添加 `archived_at` 与 `report_link`

## 通用规则
- 用 `bash: date` 获取真实日期用于文件命名，不要臆测日期
- 每个子任务用 `task` 工具派发，等待其返回结果后再进入下一阶段
- 每个阶段验收不通过时，向子任务补充上下文并要求修正，不要跳过
- Phase 4 知识架构师如反馈公司数据不足，允许其 websearch 补充调研
- 结束时向用户汇报：报告路径（md + html）、知识节点清单（按三段式）、验证置信度、遗留事项
