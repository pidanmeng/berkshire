# 计划：估值模型参数明细化 + deep-dive-update 财报超预期/低于预期评估

> 用户需求（2026-08-29）：
>
> 1. 优化调研流程和公司研究模板（deep-dive 与 deep-dive-update），给公司定估值时新增一个 section，明确：**用了哪个估值模型？每个参数给多少？为什么？受什么影响？**（如 PE 估值：乐观 PE 给多少倍、为什么；年底/预测期业绩给多少；受政策、原材料等影响）
> 2. deep-dive-update 需**结合股价**综合评价最新一期财报是**超预期还是低于预期**。

## 二、设计方案

### A. 新增模板章节「估值模型与参数明细」（核心交付）

在 `company-template.md` 与 `company-deep-dive-template.md` 中，将现有「估值区间与目标价」「目标市值」两节增强，并在其后新增统一章节「估值模型与参数明细」，取代裸表格：

```markdown
## 估值模型与参数明细（数据时点: YYYY-MM-DD）
<!-- 估值不是拍脑袋给倍数：必须回答 用哪个模型？每个参数给多少？为什么？受什么影响？与 frontmatter valuation_type / target_market_cap_yi / forward_pe / peg 同源 -->

### 1. 估值模型选择（依据 evaluate.ts 品种路由）
| 品种 | 主估值模型 | 选择理由（数据信号） | 辅助校验模型 |
|------|-----------|---------------------|-------------|
| __（growth/general/cyclical/...） | __ | __（增速/盈利/行业特征信号） | __ |

### 2. 关键参数明细（三情景，与「目标市值」表同源）
| 参数 | 悲观 | 中性 | 乐观 | 取值依据（为什么给这个数） |
|------|:----:|:----:|:----:|--------------------------|
| 预测期净利（亿元，__E） | | | | __ |
| 估值倍数（x，PE/PB/正常化EPS...） | | | | __ |
| 目标市值（亿元） | | | | 净利 × 倍数（交叉校验） |
| 目标价（元） | | | | 目标市值 ÷ 总股本 |
> 倍数取值必须写明锚定方法（如 PEG + 同业前瞻 PE + 历史分位三重锚定法，列出各锚定的具体数值与区间），禁止无依据主观给定；区间宽度反映可预测性。

### 3. 参数敏感性分析（参数受什么影响）
| 影响因素 | 影响参数 | 影响方向与幅度 | 发生概率 | 触发信号/跟踪指标 |
|---------|---------|--------------|:-------:|------------------|
| 政策（补贴/管制/贸易壁垒/产业规划） | | | | |
| 原材料/成本（价格、供给、汇率传导） | | | | |
| 竞争（价格战/产能过剩/新进入者） | | | | |
| 汇率/利率 | | | | |
| 技术代际/需求（渗透率、客户 capex、订单） | | | | |
| 治理/诉讼/地缘（其他） | | | | |
```

* 原「估值区间与目标价」「目标市值」表保留（作为快速视图），新章节承载**参数明细与依据**；「Forward PE 快照」保留。

* 目标价、目标市值、预测期净利、估值倍数四参数必须与 frontmatter `target_market_cap_yi` / `forward_pe.base_net_profit_yi` 一致。

### B. deep-dive-update 新增「本期财报 vs 市场预期」评估（超预期/低于预期）

在 `.trae/commands/deep-dive-update.md` 步骤 5（增量对比）与步骤 7（报告）中，强制产出以下章节（写入 `基本面更新` 笔记与更新报告）：

```markdown
## 本期财报 vs 市场预期（超预期/低于预期综合评估）
### 1. 业绩 vs 预期
| 维度 | 业绩预告/市场一致预期 | 实际值 | 超/低预期幅度 | 来源 |
|------|---------------------|--------|--------------|------|
| 营收/归母/扣非/毛利率/OCF... | | | |（预告区间、券商一致预期、去年同期对照）|
### 2. 股价反应（财报披露前后）
| 时间点 | 日期 | 股价/涨跌幅 | 相对大盘/板块超额 | 成交/资金面 |
|--------|------|-----------|-----------------|------------|
| 披露前 N 日 | | | | |
| 披露当日 | | | | |
| 披露后 1/3/5 日 | | | | |
### 3. 综合判定
- **结论**：超预期 / 符合预期 / 低于预期（业绩维度 + 股价维度 + 质量维度综合，说明判定依据）
- **市场反应逻辑解读**：利好兑现 / 利好出尽 / 利空出尽 / 情绪背离
- **对估值参数的含义**：预测期净利/估值倍数是否需要上修或下修，触发条件与跟踪信号是什么
```

* 业绩维度判定：实际值 vs 业绩预告区间中值 / 市场一致预期（研报/一致预期数据）/ 去年同期增速与环比。

* 股价维度判定：披露前后股价相对大盘/板块的超额表现；无行情工具时至少给出披露前后收盘价与涨跌幅（数据来源标注）。

* 若触发事件非财报（如仅为公告），本评估仍须执行但可弱化为「对最近一期已披露业绩预期的影响」。

## 四、假设与决策

1. **落点**：新章节写**正文**，不新增 frontmatter 字段（避免触发 AGENTS.md「新字段须同步 research.ts → api.ts → 展示组件」的链路成本）；frontmatter 已存 target\_market\_cap\_yi/forward\_pe/peg 作为「输出」，正文章节承载「模型选择 + 参数依据 + 敏感性」。
2. **生效范围**：deep-dive 与 deep-dive-update 强制；/research 标准/深度模式共用 company-template.md 与 knowledge-architect/report-writer 定义，故同样受约束（与用户"优化调研流程"意图一致）。
3. **存量笔记**：不回填改造既有公司笔记；新章节要求对**新调研/新更新**生效。knowledge-architect self-check 为 advisory，存量笔记缺失仅提示不阻塞。
4. **超/低预期判定口径**：业绩维度（预告区间中值/一致预期/去年同期）+ 股价维度（披露前后超额表现）+ 质量维度（如 OCF/毛利率等非表观项）三维综合，避免只看表面数字。
5. **敏感性分析证据**：取自 deep-read（政策/原材料/竞争/汇率/技术代际已在精读目标 6/9 覆盖），报告中标注置信度与出处，证据不足标「存疑」。

## 五、验证步骤

1. 模板完整性：打开修改后的两个模板，确认新章节结构完整、参数列与 frontmatter 字段口径一致。
2. 命令一致性：grep `.trae/commands/` 确认 deep-dive / deep-dive-update 对「估值模型与参数明细」「本期财报 vs 市场预期」的引用到位。
3. Agent 一致性：grep `.trae/agents/` 确认 knowledge-architect / report-writer / document-reader 对两个新要求的覆盖。
4. self-check 语法与运行：`bun run .trae/agents/knowledge-architect.md.self-check.ts <现有公司笔记目录>` 验证不报语法错误、存量笔记不硬性失败。
5. 全量测试：`bun test`（项目根）确认无回归（本次无脚本逻辑改动，主要防误改）。
6. 抽查样例（不实际执行完整 deep-dive，避免产生工作区产物）：以新易盛基本面更新为样板，人工比对新增章节结构是否可承接其现有「PE 倍数三重锚定法」内容。
