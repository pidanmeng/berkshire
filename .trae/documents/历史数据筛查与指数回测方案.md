# 历史数据筛查与指数回测 — 可行性评估与实施方案

> 日期：2026-08-30 ｜ 类型：方案设计（本阶段不动代码）
> 目标：基于现有基本面筛查工具，构建一个\*\*严格 point-in-time（无未来函数）\*\*的自定义指数回测系统。
> 指数规则（已确认默认）：基本面选股 → 每期 **10 只等权** → 每年 **3 次调仓**（4 月底 / 8 月底 / 10 月底，即一季报/中报/三季报披露后）→ 持有至下次调仓。

***

## 1. 结论先行（回答"能不能用历史数据筛查评分"）

| 维度               | 现状                                                                                            | 结论                                                              |
| ---------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 财务基本面指标（8 项评分输入） | `getIndicatorsRaw(code, report)` 支持任意历史报告期，`screen.ts` 已有 `--report/--prev-report` + JSONL 缓存 | ✅ **可直接回溯**，无需改造数据源                                             |
| 历史行情/股价          | 同花顺 10 年全市场日K Parquet dump + 复权因子 dump + 东财前复权K线                                              | ✅ **数据源已就绪**，需新增本地数据层                                           |
| 历史时点估值（PE/PB）与市值 | `getValuations` / `getMarketCapWithFallback` 均为**实时快照**；Stage A 硬过滤用的是"今天的市值 + 今天的 PE"        | ❌ **不可回溯**，需自算补齐（本方案核心新增项）                                      |
| 披露日期（报表何时可见）     | `report_date_ms` 恒为 0                                                                         | ⚠️ A 股披露截止日固定（4/30、8/31、10/31），调仓日恰在其后，**可用报告期直接映射**，个别延披公司标注即可 |
| 报表重述             | 接口返回当前时点的最终审定值                                                                                | ⚠️ A 股年报重述少见，**接受近似**，报告中注明                                     |

**总判定：可行。** 财务维度零改造即可回溯；估值/市值维度需补一个"历史时点估值计算层"（历史日K收盘价 × 报告期/TTM 财务数据自算 PE/PB、市值），并新增历史行情本地库与回测引擎。

### 2.3 三个 point-in-time 缺口（本方案要补齐的）

1. **历史时点估值/市值**：PE-TTM/PB-MRQ/市值无历史端点 → 用"历史日K收盘价 × 报告期/TTM EPS"自算（数据缺口分析文档 #6 已验证此路径可行）
2. **披露日期元数据**：`report_date_ms=0` → 用 A 股法定披露截止日（4/30、8/31、10/31）映射"调仓日可见的最新报告期"
3. **报表重述**：接口返回当前时点最终值 → 接受近似，报告注明局限

## 3. 目标架构

```
[历史财务层]  indicators?report=YYYY-N（JSONL 缓存，沿用现模式，扩展 2016-2026 各报告期）
              三表接口（annual/quarterly）→ EPS 序列（TTM 计算用）
[历史行情层]  同花顺 dump：全市场 10 年日K（未复权）+ 复权因子 → 本地 DuckDB/SQLite
              → 提供：任意日收盘价、后复权价格序列（分红再投资）
[历史估值层]  历史 PE = 调仓日收盘价 ÷ TTM EPS
              历史 PB = 调仓日收盘价 ÷ 报告期每股净资产（净资产取自资产负债表）
              历史市值 = 调仓日收盘价 × 报告期股本（股本取自资产负债表，备选当前股本近似）
[筛查层]      screen.ts 新增 --asof <调仓日> 模式：Stage A 改用历史估值/市值（不再拉实时快照）
              Stage B/C 原样复用（8 项评分 + 分池）
[指数层]      每期取评分 Top 10（GREEN 优先，按综合分排序），等权持有
[回测层]      backtest.ts：调仓日历 → 组合构建 → 期间收益（后复权）→ 基准对比 → 指标报告
```

## 4. 详细设计

### 4.1 历史财务数据层（改造现有缓存模式）

* **范围**：覆盖全部回测报告期。调仓日 → 最新可用报告期映射表：

| 调仓日          | 刚披露的报告期      | 选股用财务指标  | 复核用上期                                    |
| ------------ | ------------ | -------- | ---------------------------------------- |
| 4 月底（4/30）   | `YYYY-1` 一季报 | `YYYY-1` | `YYYY-1-1`（上年同期，ROE 连续复核用 `YYYY-1` 年报口径） |
| 8 月底（8/31）   | `YYYY-2` 中报  | `YYYY-2` | `YYYY-1`                                 |
| 10 月底（10/31） | `YYYY-3` 三季报 | `YYYY-3` | `YYYY-2`                                 |

* **TTM EPS 序列**：`getIncomeStatements(code, "quarterly", 8)` 取最近 8 期单季 `basic_eps`，TTM = 最近 4 期之和。⚠️ 实施时先验证 quarterly 返回的是**单季还是累计**口径，若为累计则用相邻期差分

* **缓存扩展**：`cache/indicators-<report>.jsonl` 沿用；EPS 序列建议并入同缓存行（一次抓取）或独立 `eps-<report>.jsonl`

### 4.2 历史行情数据层（新增）

* **首选（全市场、一次到位）**：同花顺 dump 三端点（`endpoints-market-dumps.md`）

  1. `daily-k`：全市场 10 年未复权日K（\~945 万行）
  2. `adjustment-factors`：复权事件（分红/送股/配股）
  3. `daily-k-10d`：近 10 交易日增量（日常维护）

  * 入库：预签名 URL（5 分钟有效）→ 下载 Parquet → DuckDB（或 SQLite）建表，`(thscode, date_ms)` 主键 UPSERT

  * **后复权价格序列**：由未复权价 × 复权因子自行构建（日频），用于组合收益与分红再投资计算

* **备选（逐只、兜底）**：`getKlineFromEastmoney(code, N)` 前复权日K（单次 ≤1000 根，约 4 年）；仅用于单公司精度验证与 dump 缺失补数

* ⚠️ dump 数据"最近约 10 年"，回测起点默认 **2016-07-01 之后**（首个完整回测从 2020-01 起跑通，见 4.6）

### 4.3 历史时点估值计算层（核心新增，`.trae/scripts/backtest/point-in-time.ts`）

调仓日 T 对应的历史估值（严格只用 T 及之前已披露信息）：

```
历史 PE(T)  = 调仓日收盘价(T) ÷ TTM_EPS(T)
              其中 TTM_EPS(T) = 截至 T 最新可披露的最近 4 个单季 basic_eps 之和
历史 PB(T)  = 调仓日收盘价(T) ÷ 每股净资产(最新可披露报告期)
              （每股净资产 = 期末归母净资产 ÷ 报告期股本，取自资产负债表）
历史市值(T) = 调仓日收盘价(T) × 报告期股本
              （股本取自最新可披露资产负债表；字段缺失时用当前股本近似并标注）
```

* 收盘价取**披露截止日收盘价**（4/30、8/31、10/31，非交易日顺延至前一交易日）——此时该报告期财报已可视为披露完毕，无未来函数

* PE<0（亏损）→ 亏损池，与现有 `applyUniverseFilters` 行为一致

### 4.4 point-in-time 筛查流程（`screen.ts` 新增 `--asof` 模式）

* **改动点**：

  1. CLI 新增 `--asof YYYY-MM-DD`：指定调仓日（历史回放）或缺省（维持现状=实时）
  2. Stage A 改造：`--asof` 时跳过实时估值/市值拉取，改用 4.3 自算值；名称过滤（ST/退）照旧——⚠️ 历史时点的 ST 状态无法从当前代码表回溯，**近似采用当前 ST 名单**（局限见 7）
  3. Stage B/C：不改（`parseIndicatorsYear`、`scoreRow`、`screenCompany`、`assignPool` 全部为纯函数，与行情解耦）
  4. `meta` 记录 `asOf` + `report`，产物命名带调仓日：`stage-a-2024-04-30.json` 等

* **产出**：每期一个 `screener-<调仓日>.json`（含 8 项指标 + 综合分 + 分池），是回测引擎的组合构建输入

### 4.5 指数规则（已确认）

* 选股：GREEN（明星池）优先，按综合分降序取 **Top 10**；GREEN 不足 10 只时用 YELLOW 按综合分补齐

* 加权：**等权**

* 调仓：每年 3 次（4/30、8/31、10/31 披露截止后首个交易日执行），持有至下次调仓

* 个股上限约束：单行业不超过 4 只（避免集中度风险，可调参数）

### 4.6 回测引擎（新增，`.trae/scripts/backtest/backtest.ts`）

* **调仓日历**：由年份区间 × 3 个披露截止日生成，每期产出持仓清单（来自 4.4 筛查结果）

* **收益计算**：以调仓日收盘价建仓，后复权价格序列计算持仓期间收益（含分红再投资）；组合收益 = 各持仓收益均值（等权）

* **基准**：沪深300（000300.SH），同样用后复权序列

* **报告指标**：累计收益 / 年化收益 / 超额收益 / 最大回撤 / 夏普比率 / 胜率（相对基准）/ 每期换手率 / 持仓明细

* **默认回测区间**：2018-01-01 ～ 2026-08-30（受 dump 10 年限制；首轮先跑 2020-01 起冒烟，数据完整性确认后前推）

* **产物**：`Research/00-Workspace/08-Backtest/` 下每期筛查 JSON + 回测结果 JSON + `backtest-report.md`（含收益曲线数据，HTML 报告可后续接 research-report-generator 生成）

### 4.7 新增/改动文件清单

| 文件                                        | 动作     | 内容                                                          |
| ----------------------------------------- | ------ | ----------------------------------------------------------- |
| `.trae/scripts/backtest/market-db.ts`     | 新增     | dump 下载（预签名URL）、Parquet 入库（DuckDB/SQLite）、日K/复权因子查询、后复权序列构建 |
| `.trae/scripts/backtest/point-in-time.ts` | 新增     | 历史时点 PE/PB/市值计算（4.3 公式），EPS/股本从三表序列获取                       |

## 7. 风险与已知局限

| 局限                   | 影响             | 缓解                      |
| -------------------- | -------------- | ----------------------- |
| 报表重述（接口给当前最终值）       | 早年指标可能是重述后值    | 标注；A 股重述少见，影响有限         |
| ST/退市名单不可回溯          | 历史时点可能误入/漏掉 ST | 用当前 ST 名单近似，报告中注明       |
| 股本历史变动（增发/回购）        | 历史市值精度         | 优先用报告期股本；缺失时当前股本近似      |
| quarterly 单季/累计口径未验证 | TTM EPS 可能算错   | 实施 Step 2 先验证，若累计则差分    |
| 个别公司延披财报             | 调仓日可能少用最新一期    | 映射表标注；延披公司用上一期          |
| dump 更新频率            | 回测区间尾部需增量同步    | `daily-k-10d` 定期 UPSERT |

## 8. 验证步骤（验收标准）

1. **数据层**：dump Parquet 入库成功；抽样 3 只（600519/000858/300750）收盘价与东财一致；复权因子应用后分红日价格跳空合理
2. **估值精度**：5 只样本在 3 个历史时点的自算 PE 与真实时点 PE 误差 < 15%
3. **筛查一致性**：`--asof` 模式下 2024-4 报告期的财务维度输出与既有 `latest-screener.json`（同报告期）一致；仅估值/市值维度为历史值
4. **回测冒烟**：2020-01 起约 20 期调仓全部跑通，每期 10 只持仓、无缺失；组合收益与沪深300对比曲线合理（无未来函数导致的异常跳变）
5. **报告**：`backtest-report.md` 含累计/年化/超额/回撤/夏普/胜率/换手与持仓明细
