# 投研系统优化计划

> 基于根目录 `TODO.md` 的系统性优化方案。本计划包含对 TODO 原方案的解读、改进建议，以及可直接执行的实施步骤。

---

## 一、摘要

本次优化围绕四个核心方向：
1. **搜索脚本瘦身**：剥离低质量 Bing 搜索，明确 Agent 使用系统自带 web search 工具做通用搜索；脚本仅保留证券专用功能（财报/研报获取）。
2. **公司调研前置确认**：产业调研流程中，在启动 Phase 1 之前，先从板块成分股中按成交量排序，让用户选择具体要调研的公司。
3. **新增单公司深度调研流程**：`/deep-dive [公司名]`，支持追加到已有产业调研产出。
4. **目标价区间纳入研究产出**：在公司笔记和报告中增加基于多估值方法的目标买入/卖出区间。

---

## 二、当前状态分析

### 2.1 搜索脚本现状

| 文件 | 当前功能 | 问题 |
|------|---------|------|
| `search.ts` | Bing HTML 抓取搜索 | 反爬严重、结果质量差、已标注"可能触发反爬" |
| `stock.ts` | 名称→代码、公告、研报、财报PDF、同花顺财务数据(--hithink)、--all | 功能臃肿；同花顺数据与 evaluate.ts / hithink.ts 重复；Bing 依赖 |
| `hithink.ts` | 同花顺 API 客户端 + CLI 入口 | CLI 入口与 stock.ts --hithink 重复；API 函数被 evaluate.ts 依赖 |
| `fetch-source.ts` | URL 正文提取（jina→readability→regex） | 功能合理，保持 |
| `fetch-file.ts` | PDF/文件下载 + pdfjs 文本提取 | 功能合理，保持 |
| `web-search.test.ts` | Bing 解析测试 | 随 Bing 移除而废弃 |
| `test-api.ts` | 同花顺 API 连通性测试 | 随 hithink CLI 移除而废弃 |

### 2.2 调研流程现状

当前 `/research [主题]` 直接启动 Phase 1→6，**没有前置的公司选择环节**。InfoHunter 自行决定调研哪些公司，用户无法干预。这导致：
- 可能遗漏用户关心的重点公司
- 可能调研了用户认为不重要的公司
- 成分股选择不透明

### 2.3 单公司调研现状

当前没有独立的单公司深度调研命令。用户只能通过完整的 `/research [行业]` 间接获得公司分析，无法对单一标的做快速深度扫描。

### 2.4 目标价现状

`company-template.md` 和 `report-template.md` 中有"估值判断""安全边际"等定性描述，但**没有结构化的目标买入/卖出价区间字段**。evaluate.ts 输出估值快照（PE/PB 当前值），但未基于历史分位或同业对比计算目标价区间。

## 三、待修改项与改进方案

### 任务 1：搜索脚本重构（优先级：高）

#### 3.1.1 删除 Bing 搜索（`search.ts`）

**TODO 原文**：删除 Bing 信源，告知 Agent 需要通用搜索时使用自带的 web search 工具。

**实施方案**：
- 删除 `search.ts` 中的 `parseBingResults()`、`searchBing()` 及 main 函数中的 Bing 调用逻辑
- 将 `search.ts` 改造为**纯信源导航脚本**：保留 `--list`（列出信源索引）和 `--search`（按类型推荐信源搜索 URL）功能
- 删除 `web-search.test.ts`

**更好的方案**：将信源导航功能合并到 `sources.ts` / `fetch-source.ts` 的 `--list`/`--search` 中，最终**删除 `search.ts` 文件本身**，减少一个脚本维护点。

#### 3.1.2 精简 `stock.ts`

**TODO 原文**：搜索脚本只提供「获取财报」「获取机构研报」，移除同花顺相关代码。

**实施方案**：
- 保留 `--name`（名称→代码）、`--announcements`（公告）、`--reports`（研报）、`--financial`（财报PDF）
- **删除** `--hithink` 和 `--all` 选项及对应的 `printHithinkData()` 调用
- `stock.ts` 不再 `import` hithink.ts 的函数
- 删除 `test-api.ts`

#### 3.1.3 保留 `hithink.ts` 作为纯 API 库

**说明**：`evaluate.ts`、`quality-screen.ts` 等脚本依赖 hithink.ts 的 API 函数（`getSnapshot`、`getValuations` 等），因此 hithink.ts **不能删除**，但需要移除其 CLI main 函数，仅保留导出函数。

#### 3.1.4 更新提示词

需要修改的文件：
- `info-hunter.md`：删除所有提及 `search.ts` 做 Bing 搜索的描述；明确"通用搜索请使用系统 websearch 工具"
- `research-web-search/SKILL.md`：删除 Bing 搜索相关说明；更新脚本列表
- `knowledge-architect.md`、`report-writer.md` 中如有引用 `stock.ts --hithink` / `--all` 的，改为引用 `hithink.ts` 或直接说明由 evaluate.ts 提供

### 任务 2：公司选择交互（优先级：高）

#### 3.2.1 新增板块成分股查询脚本

**TODO 原文**：先从同花顺找到相关板块，以及成分股，按成交量排序，用户选择。

**分析与改进**：
- 同花顺 API（hithink-finance）**没有板块成分股接口**（经查阅 endpoints-meta.md / endpoints-prices.md，仅有 tickers/search 和 tickers/list，无板块查询）。
- **更好的方案**：使用**东方财富**的板块成分股接口，免费、稳定、字段丰富（含成交额、换手率、市盈率等）。

**新增脚本**：`.trae/skills/research-web-search/scripts/sector.ts`

功能设计：
```
bun run sector.ts --search "PCB"              # 搜索板块关键词，返回匹配板块列表
bun run sector.ts --code BK0429               # 获取某板块成分股，按成交额排序
bun run sector.ts --name "电子元件" --top 20   # 按板块名获取前20只成分股
```

数据来源：东财 `https://push2.eastmoney.com/api/qt/clist/get`（板块成分股）+ `https://searchapi.eastmoney.com/api/suggest/get`（板块搜索）。

输出格式：Markdown 表格（序号 | 代码 | 名称 | 最新价 | 涨跌幅 | 成交额 | 市盈率），按成交额降序。

#### 3.2.2 修改 `research.md` 编排流程

在 Phase 1 之前增加**公司确认环节**：

```markdown
## 前置：公司选择（新增）

1. 调用 `sector.ts --search "主题"` 查找相关板块
2. 取最相关 1-3 个板块，调用 `sector.ts --code <板块代码> --top 30` 获取成分股（按成交额排序）
3. 向用户展示成分股列表（前 15-20 只），请用户选择要重点调研的公司（多选）
4. 用户确认后，将选中的公司列表写入 `00-Workspace/01-Inbox/YYYY-MM-DD-主题-company-selection.md`
5. InfoHunter Phase 1 采集时**优先覆盖用户选中的公司**，再补充其他代表性公司
```

> **为什么更好的方案**：不仅让用户选择公司，还**记录选择过程**到中间产物，便于后续回溯"当时为什么选这几家"。

### 任务 3：单公司深度调研流程（优先级：中）

#### 3.3.1 新增命令：`/deep-dive [公司名]`

**TODO 原文**：新增单独调研某家公司的流程，如果已经有对应的产业调研产出，则 append 到已有的产出中。

**实施方案**：

新增 `.trae/commands/deep-dive.md`：

```markdown
---
description: 对单一公司进行深度调研，支持追加到已有研究。用法：/deep-dive [公司名]
---

1. **检查已有研究**：搜索 `Research/10-Knowledge/**/02-公司研究/<公司名>-*.md`
   - 若存在：读取现有笔记，提取已有数据和结论
   - 若不存在：作为全新公司研究

2. **快速数据采集**（InfoHunter 精简模式）：
   - `stock.ts --name <公司>` → 代码
   - `stock.ts --code <代码> --financial` → 财报PDF
   - `stock.ts --code <代码> --reports` → 研报
   - `evaluate.ts --code <代码>` → 四大师框架 + 估值快照
   - `hithink.ts --code <thscode> --valuation --snapshot` → 实时估值

3. **质量筛查**：`quality-screen.ts --file <草稿>`

4. **写入知识库**：
   - 若已有笔记：追加到新段落，frontmatter 的 `updated` 字段更新，追加 `deep_dive_at` 字段
   - 若新笔记：按 `company-template.md` 全新创建

5. **生成单公司报告**：`Research/20-Reports/YYYY-MM-DD-<公司名>-deep-dive-report.md`（简版，不含行业全景）
```

**更好的方案**：
- 不仅 append，还要做**增量对比**：在笔记中增加"本次更新 vs 上次研究的变化"段落（估值变化、业绩变化、护城河变化）。
- 单公司报告使用**专用模板**（比产业报告更聚焦），新增 `company-deep-dive-template.md`。

### 任务 4：目标价区间（优先级：中）

#### 3.4.1 修改模板

**`company-template.md`**：
- 在"估值与股价快照"章节后，新增"**估值区间与目标价**"小节：

```markdown
## 估值区间与目标价（安全边际视角）

| 估值方法 | 假设条件 | 目标价区间（元） | 当前价对比 | 置信度 |
|---------|---------|----------------|-----------|--------|
| PE 估值法 | 合理 PE 15-20x | 80-100 | 低估 / 合理 / 高估 | 中 |
| PB 估值法 | 合理 PB 2-3x | 70-90 | — | 低 |
| DCF 估值法 | WACC 8%, 永续 3% | 85-110 | — | 低 |
| **综合目标区间** | — | **80-100** | — | — |

- **目标买入价**（安全边际买入）：_ 元（基于保守估值打 7-8 折）
- **目标卖出价**（高估卖出）：_ 元（基于乐观估值上沿）
- **当前操作建议**：观望 / 逢低关注 / 持有 / 高估可考虑减仓
```

**`report-template.md`**：
- 在"投资建议"章节中，要求为每家公司给出"目标买入价区间"和"目标卖出价区间"

#### 3.4.2 增强 `evaluate.ts`

在 `evaluate.ts` 的"估值与股价快照"章节中，自动计算并输出：
- 基于当前 PE / PB 的**历史分位**（需要 K 线数据）
- 基于同业 PE 中位数的**相对估值区间**
- 输出格式：`目标买入价 = 合理估值下限 × 0.8`（安全边际折扣）
- 输出格式：`目标卖出价 = 乐观估值上限`

> **更好的方案**：不强行给一个数字，而是给出**三种情景**（悲观/中性/乐观）下的估值区间，让用户理解假设条件。这更符合价值投资"称重机"理念——估值是区间，不是精确数字。

## 五、关键决策与假设

1. **板块数据源选择**：使用东方财富而非同花顺，因为同花顺 API 无板块成分股端点，东财接口免费稳定。
2. **search.ts 处置**：建议彻底删除（合并功能到 fetch-source.ts），而非保留空壳。减少维护面。
3. **hithink.ts CLI 删除**：evaluate.ts 和 quality-screen.ts 通过 `import` 调用 hithink.ts 的函数，不走 CLI，因此 CLI 入口可安全删除。
4. **目标价计算方式**：采用"三情景区间法"（悲观/中性/乐观），而非单点目标价。更符合四大师投资哲学。
5. **deep-dive 与增量模式区别**：`/research --incremental --company-only` 是产业调研的子集；`/deep-dive` 是独立命令，聚焦单公司，输出格式不同（简版报告 vs 完整产业报告）。

## 六、风险与回退方案

| 风险 | 影响 | 回退方案 |
|------|------|---------|
| 东财板块接口变动 | sector.ts 失效 | 回退到手动让用户输入公司列表；sector.ts 中加入接口异常捕获 |
| evaluate.ts 目标价计算依赖 K 线数据量大 | 脚本变慢 | K 线仅取最近 250 日（1年）计算分位；或改为仅输出当前估值定性判断 |
| 删除 search.ts 后某些 Agent 仍引用 | 运行时错误 | 全局 grep 检查所有 .md 文件中的 `search.ts` 引用，一并更新 |
| 用户不选公司直接跳过 | 流程阻塞 | sector.ts 展示后提供"跳过，由 Agent 自行选择"选项 |
