# 估值追踪系统建设计划

> 基于现有投研 Agent 产出（公司笔记 + 质量筛查 + evaluate.ts）构建的市值追踪系统。
> 目标：① Web 监控终端实时判断已调研公司是否跌到安全边际；② 全面数据看板（Tag 归类 + 财务/股价展示）；③ 依据财报/公告截止日期自动提示基本面是否需要更新。

---

## 一、摘要

本计划分三大任务，全部决策已定，可直接执行：

1. **结构化产出改造（投研管线）**：为每份公司笔记增加机器可读的追踪字段——六维十分制分数（0.1 精度）、各维文本总结、目标市值（悲观/合理/乐观）、Forward PE（影响因素+发展方向）、财报/公告截止日期。**综合评分不人工给出，由六维分数经代码中可修改的权重公式计算**。同步改造 `company-template.md`、Agent 提示词、`evaluate.ts`，并编写**存量回填脚本**让现有 60+ 家公司笔记立即可追踪。
2. **市值追踪系统（Web）**：**后端 API 用 Elysia（Bun 原生框架）**，前端用 Next.js（纯 UI/SSR，不承载 API）。含 Tag 筛选仪表盘、实时市值 vs 安全边际分档、K 线图、基本面更新检测，暗黑主题（遵循 `design.md`）。
3. **集成与验证**：更新 `AGENTS.md` 共享脚本表，端到端验证。

## 二、技术选型与结论

### 2.1 架构总览（前后端分离）

```
┌─────────────────────────────┐     ┌──────────────────────────────┐
│  Next.js 15 (App Router)    │     │  Elysia (Bun) 后端 API        │
│  纯 UI / SSR / 客户端轮询     │◄────│  /api/companies /api/quotes   │
│  不写 route handler          │ HTTP │  /api/kline/:code            │
│  (保留之前前端二选一的 Next)   │     │  /api/fundamentals/:code     │
└─────────────────────────────┘     └──────────────┬───────────────┘
                                                   │
                              ┌────────────────────┼────────────────────┐
                              │ hithink REST       │ 东财 push2 批量     │ 巨潮 cninfo
                              │ (行情/K线/估值)      │ (价格/涨跌/总市值)   │ (公告/财报检测)
                              └────────────────────┴────────────────────┘
                                  数据层：lib/research.ts (Markdown 解析)
                                          lib/quote.ts / lib/cninfo.ts
                                          lib/safety.ts / lib/store.ts
```

- **Next.js 只做 UI**：服务端组件负责首屏渲染（请求时从 Elysia 拉数据），客户端组件负责轮询刷新与交互（直连 Elysia，开启 CORS）。
- **Elysia 承载全部 API 与数据层**：解析 Markdown、调用三路外部 API、安全边际计算、SQLite 存储、缓存。Elysia 是 Bun 原生框架，与仓库现有 `bun` 脚本体系完全同构。

### 2.2 直接回答：SQLite 能否一键部署到 Vercel？

文件型 SQLite 在 Vercel Serverless 上无法持久化。本架构下：

- **本地/自托管后端（推荐）**：Elysia 跑在持久主机（本机 / VPS / Railway / Fly.io）→ **`bun:sqlite` 文件库直接可用**，SQLite 语义完整保留。
- **Vercel Serverless 后端（可选）**：Elysia 支持导出 `fetch` handler 部署为 Vercel Function，此时文件 SQLite 不可持久化 → 存储层换 **Turso（libSQL，SQLite 兼容托管库，HTTP 驱动）**。
- **前端**：Next.js 一键部署 Vercel，通过 `API_BASE_URL` 环境变量指向 Elysia 地址。
- **核心原则不变**：Markdown 是调研数据的唯一事实源，数据库只存动态状态（价格快照、基本面检测缓存）。

### 2.3 技术栈清单

| 领域 | 选型 | 理由 |
|------|------|------|
| 后端 API | **Elysia（Bun 原生）+ TypeScript** | 用户指定；与现有 bun 脚本体系同构，支持 Bun/Node/Serverless 多运行时 |
| 前端框架 | **Next.js 15（App Router）+ TypeScript**（纯 UI，无 route handler） | 用户二选一中的动态方案；SSR 首屏 + 客户端轮询 |
| 图表 | **ECharts 5.5**（同 `design.md` 规范） | 与现有 HTML 报告图表体系一致 |
| 调研数据源 | **Git 内 Markdown frontmatter**（gray-matter 解析） | 单一事实源，随仓库部署 |
| 实时行情 | 同花顺 hithink REST：`/prices/snapshot`、`/prices/historical`、`/valuations/snapshot` | 已实测，文档在 `.trae/skills/hithink-finance/` |
| 市值（同花顺不含） | **东财 push2 批量接口** `ulist.np/get`（`f2` 价格、`f3` 涨跌%、`f20` 总市值） | 已实测：一次请求取回多只股票价格+总市值 |
| 基本面更新 | **巨潮 cninfo**（复用 `stock.ts` 的 `queryAnnouncements` 逻辑） | 判断「调研截止后是否出了新财报/预告」 |
| 本地数据库 | **`bun:sqlite`** | 零依赖、SQLite 语义，持久主机可用 |
| Serverless 数据库（可选） | **Turso / libSQL**（`@libsql/client` HTTP） | 仅当后端以 Vercel Function 部署时启用 |
| 综合评分 | **`.trae/scripts/valuation/composite.ts`**（权重公式单源） | 六维加权，权重代码内可改（见 §4.1.5） |

### 3.2 缺口（需新建）

1. **十分制分数**：现有评分是星级（1-5，半星），且放在 frontmatter **注释**里，非结构化数据。
2. **各维文本总结**：评分卡「核心判断」列已有，但无统一机器可读字段。
3. **综合评分计算**：目前人工给「综合星级」，未由六维加权得出；需改为代码内可调权重公式计算。
4. **目标市值**：笔记里是**每股目标价**，无目标市值（亿元）；evaluate.ts 未输出。
5. **Forward PE**：部分笔记有散文式描述（如宁德时代「Forward PE 约 19x」），无结构化字段。
6. **财报/公告截止日期**：完全缺失，无法自动判断基本面是否需更新。
7. **市值数据源**：同花顺估值端点不含市值，需东财 push2 补齐。

```ts
export const COMPOSITE_WEIGHTS = {
  capability: 1 / 6,      // 能力圈（巴菲特）
  moat: 1 / 6,            // 护城河（巴菲特）
  business_model: 1 / 6,  // 生意模式（段永平）
  management: 1 / 6,      // 管理层诚信（段永平+本分）
  inversion: 1 / 6,       // 反向检查清单（芒格）
  historical: 1 / 6,      // 历史类比与时间框架（李录）

/** 六维分数 → 综合分（0-10，1 位小数） */
export function computeComposite(
  scores: { capability?: number; moat?: number; business_model?: number;
             management?: number; inversion?: number; historical?: number },
  weights: Partial<typeof COMPOSITE_WEIGHTS> = COMPOSITE_WEIGHTS,
): number | null {
  // 缺失维度按剩余权重归一化；全部缺失返回 null
}
```

引用方：`evaluate.ts`、`backfill.ts`、Elysia 数据层（`lib/research.ts`）——**三处共用同一公式**，改一处全局生效。

#### 1.4 扩展 `.trae/scripts/evaluation/evaluate.ts`

新增输出（全部由脚本基于现有 API 计算，Agent 可修订）：
- **总股本/总市值**：新增 `hithink.ts` 导出 `getMarketCapFromEastmoney(thscodes)`（东财 `ulist.np/get`，`f2`/`f20` 批量）；evaluate.ts 顺带输出总市值（亿元）。
- **TTM 净利**：`总市值 / PE-TTM`（估值端点与市值同源时点）。
- **Forward PE**：新增 CLI 参数 `--forward-growth <0.25>`（预测期净利增速，缺省取 `yoy_net_profit`）；`Forward PE = 当前市值 / (TTM净利 × (1+增速))`，输出基准期（当前财年+1）。
- **目标市值三情景**：`情景市值 = 预测净利 × 情景PE假设`（悲观/中性/乐观 PE 沿用现有估值方法路由的参考区间），与现有每股目标价相互校验（目标价 × 总股本 ≈ 目标市值）。
- **综合评分**：调用 `composite.ts` 的 `computeComposite`，由六维分数输出综合分（六维分数仍由 Agent 裁定，脚本只算综合）。
- 输出 Markdown 段落「目标市值与 Forward PE 框架」，供 knowledge-architect 采纳。

> 注：`hithink.ts` 新增东财函数与现有同花顺 API 客户端职责略有出入，但均为「行情数据获取」，命名上以 `getMarketCapFromEastmoney` 明示来源，不改动既有接口。

扫描 `Research/10-Knowledge/*/02-公司研究/*.md`，对缺新字段的笔记自动推导并写回 frontmatter（标记 `backfilled: true` + `backfilled_at`）：

#### 2.2 数据层设计

**来源解析 `server/lib/research.ts`**：`RESEARCH_ROOT`（默认仓库根）下扫描 `Research/10-Knowledge/*/02-公司研究/*.md`（含「公司概览」），gray-matter 解析 frontmatter：
- 必读：`stock_code`、`name`、`tags`、`industry`、`sub_industry`、`scores`、`target_market_cap_yi`、`forward_pe`、`research_cutoff`、`quality_verdict`（正则从「筛查结论」行取）、`quality_score`（正则从「综合质量分」行取）；
- 缺失字段 → `null`，前端显示「数据不完整」，不阻断渲染；
- **综合分 = `computeComposite(scores)`**（复用 §1.1 公式，权重改一处全局生效）；
- 结果按目录 mtime 缓存（60s），兼容新旧两种 frontmatter。

**存储 `server/lib/store.ts`**（接口 4 方法，多实现）：
```sql
CREATE TABLE IF NOT EXISTS price_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  thscode TEXT NOT NULL, ts INTEGER NOT NULL,
  price REAL, market_cap REAL, pe_ttm REAL, pb_mrq REAL, change_pct REAL

CREATE INDEX IF NOT EXISTS idx_snap ON price_snapshots(thscode, ts);
```

驱动选择：本地/持久主机 → `bun:sqlite`；后端 Serverless（Vercel Function）且配了 `TURSO_URL` → turso；两者都不可用 → 内存 Map 实现（当前请求生命周期，降级）。

**行情客户端 `server/lib/quote.ts`**：
- 批量快照：东财 `ulist.np/get?secids=<0.300750,1.688041...>`（secid 前缀：沪=1，深=0，由 thscode 后缀推导）→ 价格/涨跌/总市值；同花顺 `/prices/snapshot`（批量）与 `/valuations/snapshot`（批量）→ PE/PB/PS/PCF；三者并发，任一失败降级为部分字段，不整体失败。
- K 线：同花顺 `/prices/historical`（复用 `hithink.ts getKline`）。

**安全边际 `server/lib/safety.ts`**（核心监控逻辑）：
```
分档 zone(current_cap_yi, tgt)：
  current_cap ≤ tgt.pessimistic  → "深度低估"（安全边际充足）🟢
  ≤ tgt.neutral                  → "低估区间" 🟢
  ≤ tgt.optimistic               → "合理区间" 🟡
  > tgt.optimistic               → "高估区间" 🔴
  tgt 缺失                       → "无估值锚点" ⚪
附加指标：
  margin_vs_pess = (pessimistic − current) / pessimistic   # >0 表示已低于悲观目标
  distance_to_neutral = (neutral − current) / neutral
  distance_to_opt = (optimistic − current) / optimistic
```
展示：每家公司卡片/行内显示分档徽标 + 相对悲观目标的偏离 %；「深度低估」家数在页头汇总。

**基本面更新检测 `server/lib/cninfo.ts`**：移植 `stock.ts` 的 `searchCninfo`（名称→orgId）+ `queryAnnouncements`（category=ndbg/bndbg/yjbb，即年报/半年报/业绩报表）。检测逻辑：
```
latest_report_announced = max(公告日期, 类别∈{ndbg,bndbg,yjbb})
if research_cutoff.report_period 为空 → needs_update=null（无法判断）
elif latest_report_announced > research_cutoff.announcement_date → needs_update=true（列出新公告）
else → needs_update=false
```
结果写 `fundamental_checks`，TTL 6h；前端显示「基本面需更新 ⚠️」徽标。

## 五、关键设计决策（锁定）

1. **前后端分离**：Next.js 不写任何 route handler，所有数据经 Elysia API；前端仅 UI/SSR + 客户端轮询（Elysia 开 CORS）。
2. **Markdown 为唯一事实源**：追踪系统不复制公司数据到数据库，请求时解析；数据库仅存动态状态。保证与 Obsidian 工作流一致、随 Git 部署。
3. **综合评分由代码计算**：`composite.ts` 是权重公式唯一来源，evaluate.ts / backfill.ts / 追踪系统三处共用；修改权重后重算即全局生效。模板与提示词明确「综合分不人工填写」。
4. **十分制分数换算规则**：`十分制 = 星级 × 2`（星级含半星 0.5 → 0.1 精度），六维分数在笔记中与星级并存，模板注明换算关系。
5. **目标市值一致性**：目标市值由「目标每股价格 × 总股本」推导并与「预测净利 × 情景 PE」交叉校验；总股本 = 东财 f20 ÷ f2（实时）。
6. **Forward PE 基准**：`base_period` 统一为「最近年报财年 + 1」（如 2025 年报后 → 2026E）；`base_net_profit_yi` 必须给出以便复核。
7. **`research_cutoff.announcement_date`** 为「调研完成日」，巨潮检测以此日之后的新公告为准。
8. **降级策略**：任一外部 API 失败 → 该字段显示「—」并标记数据源异常，不阻断页面；数据库不可用 → 内存降级。
9. **环境变量**：`HITHINK_FINANCE_API_KEY`（同根脚本优先级链，仅存 Elysia 端）；`API_BASE_URL`（前端指向 Elysia）；`RESEARCH_ROOT` 默认仓库根；`TURSO_URL`/`TURSO_AUTH_TOKEN` 可选。
10. **安全**：API Key 只存在于 Elysia 服务端 env；东财/巨潮为公开接口无需 Key。

- 六维权重默认均分（各 1/6），与 AGENTS.md 现有「六维各占 1/6」口径一致；如需调整只改 `composite.ts`。

## 七、验证步骤

1. **脚本语法**：新增/修改的 TS 脚本全部通过 `bun build --no-bundle`（exit 0）。
2. **综合评分公式**：为 `composite.ts` 写最小单测（固定六维分数 → 断言综合分；改权重 → 断言变化；缺维度 → 断言归一化）。

5. **Elysia 端到端**：`bun --cwd valuation-tracker run server/index.ts` 启动后 curl 验证：
   - `GET /api/companies` 返回合并列表（含实时市值/分档/综合分）；
   - `GET /api/kline/300750.SZ?days=250` 返回 K 线；

8. **权重修改验证**：临时改 `composite.ts` 权重（如 `moat: 0.5`），重跑 evaluate.ts 与 `/api/companies`，综合分同步变化后还原。
