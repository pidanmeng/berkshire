# 研报生产流程

每篇研报都不是「搜索一下再写」，而是由一套**六阶段串行、逐阶段验收**的 Agent 流水线产出。任何一阶段的验收不通过，都会打回补充，绝不跳过、绝不糊弄。

## 三层调研结构

每篇研报覆盖三个层级，由各阶段协同保证：

| 层级 | 知识库位置 | 考察内容 |
|------|-----------|---------|
| 行业级 | `10-Knowledge/XX-行业/00-行业概览/` | 行业全景、产业链图谱、政策 |
| 细分行业级 | `10-Knowledge/XX-行业/01-细分行业/` | 按投资意义识别细分赛道（宁缺毋滥） |
| 公司级 | `10-Knowledge/XX-行业/02-公司研究/` | 公司概览、财务、竞争格局（优劣势） |

采集充分性标准：**关键论点 ≥1 权威来源、核心数据 ≥2 独立来源交叉验证**（业绩类数据回法定披露平台核对），财报原文优先。

## 六阶段流程

| 阶段 | 角色 | 产出 | 验收要点 |
|------|------|------|---------|
| Phase 1 信息获取 | 信息猎手 InfoHunter | `01-Inbox/YYYY-MM-DD-主题-raw.md` | 三层均有实质采集、关键论点有 URL 来源锚点、核心数据 ≥2 独立来源 |
| Phase 1.5 原文精读 | 文档精读官 DocumentReader | `02-Processing/YYYY-MM-DD-主题-deep-read.md` | 9 大精读目标全覆盖、最近 3 个完整财年年报精读、**多空论证（Bull/Bear Case）**完整 |
| Phase 2 信息处理 | 信息炼金师 InfoAlchemist | `02-Processing/YYYY-MM-DD-主题-processed.md` | 口径标准化、按三层归类、核心投资指标完整 |
| Phase 3 交叉验证 | 交叉验证官 CrossValidator | `03-Validation/YYYY-MM-DD-主题-validated.md` | 逐条置信度评分（1-10）、反共识检验、管理层诚信检查 |
| Phase 4 信息整理 | 知识架构师 KnowledgeArchitect | `10-Knowledge/**` 三段式 + MOC | 高置信度（≥8 分）信息入库、双链校验、质量筛查嵌入 |
| Phase 5 报告生成 | 报告撰写官 ReportWriter | `20-Reports/YYYY-MM-DD-主题-report.md` + `.html` | Markdown + HTML 双份、多空论证综合裁决、增长与护城河可持续性分析 |
| Phase 6 归档 | 编排器 | 中间产物移入 `04-Archive/` | frontmatter 添加 `archived_at` 与 `report_link` |

### 关键环节：原文精读（Phase 1.5）

带着投资目的精读财报 / 研报 / 公告原文，搞清：

1. 增长飞轮与业务模型
2. 财务状况
3. 竞争格局
4. 管理层质量
5. 风险与逆向检查
6. 历史类比

**强制覆盖最近 3 个完整财年年报**，精读后必须回答：

- 基本面是否逐年变好？
- 三年年报是否连贯（口径 / 会计政策 / 数字衔接）？
- 管理层是否诚实（前后表述与数据一致性）？

> **No-Go 红线**：三年连贯性断裂或管理层不诚实 → 必须在 deep-read 中显式标注，相关结论不得乐观化。

### 关键环节：多空论证（Bull / Bear Case）

基于**同一套原文证据**完成多空双视角论证：

- **多方**：增长飞轮、护城河拓宽、财务质量、估值安全边际
- **空方**：增长见顶、护城河侵蚀、财务红旗、估值过高、产能过剩与地缘风险

双方均须原文引用、区分事实与观点、预判对方论点并回应、诚实记录本方脆弱点。报告撰写时综合产业理解、行业周期、国际形势、政策形势等外围因素做**最终裁决**，多空分歧点显式标注并给出裁决理由。

## 质量体系（三层门禁）

| 层级 | 机制 | 说明 |
|------|------|------|
| 第一层 | 阶段内自检 | 每个 Agent 提交前运行 self-check 脚本自动检查，不通过自动修正 |
| 第二层 | 阶段间验收 | 编排器用评分卡验收（完整性 / 准确性 / 投资视角，各 0-10），总分 &lt;24 打回 |
| 第三层 | 发布后复盘 | 7 天质疑检查、30 天风险吻合度、90 天预测准确度，更新 KQI |

**关键质量指标（KQI）**：来源覆盖率 >90%、高置信度占比 >70%、四大师覆盖率 100%、返工率 &lt;15%、知识复用率 >50%。

## 常见命令

| 命令 | 用途 |
|------|------|
| `/research [主题]` | 完整投研流程（`--mode standard/fast/deep/incremental`） |
| `/search [查询]` | 仅 Phase 1 信息获取 |
| `/validate [文件]` | 仅 Phase 3 交叉验证 |
| `/report [主题]` | 基于已有知识生成报告 |

| `/sync-links` | 修复断链与缺失 properties |
| `/update-moc` | 更新 MOC 索引 |
| `/screen` | A 股全市场初筛 |

## 流程模式

- **标准模式**（默认）：全新主题首次覆盖，全量串行 + 原文精读
- **快速模式**：已有覆盖且时间 &lt;90 天，精简为单轮采集 + 精读 + 验证
- **深度模式**：重大投资决策前（`--decision-critical`），强制四大师评估 + 财报精读全量覆盖 + 回溯 3 年历史
- **增量模式**：补充特定公司/赛道（`--company-only` / `--sector-only`），定向搜索 + 追加写入

## 支撑脚本

研报生产全程由 bun 脚本支撑：财报下载与文本提取（`stock-data/stock.ts` + `file-ingestion/fetch-file.ts`）、四大师评估与估值路由（`evaluation/evaluate.ts`）、质量筛查（`quality-gate/quality-screen.ts`）、全市场初筛（`screener/screen.ts`）等，具体用法见根目录 `AGENTS.md` 的「共享脚本用法」章节。
